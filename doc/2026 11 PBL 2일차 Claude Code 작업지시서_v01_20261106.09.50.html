■ 공통 규칙 - 매 교시 첫 지시에 붙임

작업 규칙
1. 원가·거래처·개인 이름은 쓰지 않는다. 품명은 「제품A」처럼 바꿔 쓴다.
2. 어제 만든 Task 39개 기준 데이터와 역산 엔진을 그대로 쓴다. 기준 데이터를 고치지 않는다.
3. 날짜 계산은 영업일 기준이다. 공휴일과 공동연차를 뺀다.
4. 결과를 말로 주지 말고, 실행한 명령과 출력으로 보여 준다.
5. 파일을 고치기 전에 무엇을 고칠지 먼저 말한다.
6. 모르는 값은 지어내지 않고 「확인 필요」로 남긴다.

■ 교시별 지시문 - Claude Code 입력창에 붙여 넣음

1교시 · 일치 테스트 자동화

어제 만든 역산 엔진이 엑셀(NB Scheduling)과 같은 날짜를 내는지 자동으로 확인하는 시험을 만들어 줘.
- 입력: 출시일 1개, Task 39개 기준 데이터, 엑셀에서 옮긴 Task별 시작일·종료일
- 비교: Task마다 시작일·종료일이 같은지
- 출력: 일치 수, 어긋남 수, 어긋난 Task의 번호·이름·엑셀 값·엔진 값 표
- 완료 기준: 어긋남 0건. 어긋나면 원인을 Task 번호별로 적고 엔진은 고치지 말고 멈춰.
- 시험은 한 명령으로 다시 돌릴 수 있게 해 줘.

(단위: 영업일)
신호판정 조건(안)비고

3교시 · 간트 타임라인

Task 39개를 간트 차트로 보여 주는 HTML 한 장을 만들어 줘.
- 가로축: 날짜, 위쪽에 D-주차(출시일 기준 D-26주 … D-0주) 표시
- 세로축: Task 번호·이름, 단계별로 묶음
- 막대: 시작일~종료일. 선후관계가 있는 Task는 선으로 잇기
- 출시일은 세로 선 하나로 표시
- 시험값: 가상 출시일 2027-03-26으로 그려서 1교시 엔진 값과 막대 날짜가 같은지 확인
- 외부 서버에 올리지 말고 파일로만 만들어.

4교시 · 신호등·동시 진행

3교시 화면에 신호등 열을 붙여 줘.
- 판정은 2교시 표의 조건을 그대로 쓴다. 기준값은 설정 칸 하나로 빼서 바꿀 수 있게.
- Task마다 실적 완료일 칸을 둔다(비어 있으면 미완료).
- 제품 2개 이상을 한 화면에서 고를 수 있게 하고, 같은 주에 겹치는 Task를 목록으로 보여 줘.
- 시험: 실적 완료일을 일부러 늦게 넣어 빨강이 뜨는지 확인.

5교시 · 지연 흡수 규칙(이론) - 정리할 내용

  • C-01: 출시일은 고정한다. 앞 Task가 늦으면 뒤 Task의 여유에서 먼저 흡수한다.
  • 흡수 구간: 시제품 수령 전 구간까지.
  • 한도 초과: 여유가 모자라면 모자란 영업일만큼 출시일 영향을 숫자로 낸다.

6교시 · 흡수 로직·지연 알림

5교시 규칙대로 지연을 흡수하는 함수를 만들어 줘.
- 입력: 늦어진 Task 번호, 늦어진 영업일 수
- 처리: 시제품 수령 전 구간의 뒤 Task 여유에서 차례로 흡수. 출시일은 바꾸지 않는다.
- 출력: 흡수한 Task와 흡수량 표, 남은 지연 영업일, 출시일 영향(영업일·날짜)
- 남은 지연이 0보다 크면 「지연 알림」 한 줄을 화면 위쪽에 띄운다.
- 시험 3건: 지연 0일 / 여유 안에서 흡수 / 여유 초과(출시일 영향 발생)
